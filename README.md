# 校园通 CampusQA · 校园事务智能问答系统

面向高校新生的校园事务问答助手。回答只来自校内资料，每一条结论都带出处角标，可以点开看原文；资料里没有的，它直接说没有。

> 本项目为「AIGC 创意应用」方向课程作业。系统可离线运行，零第三方依赖。

---

## 一、30 秒启动

**方式一：双击**

双击项目根目录的 `启动校园通.bat`。

**方式二：命令行**

```powershell
cd aigc-campus-qa
node app/server.mjs
```

打开 <http://127.0.0.1:7788> 即可使用；运营看板在 <http://127.0.0.1:7788/admin>。

> 只需要 Node.js ≥ 18（本项目在 Node 24 上验证）。不需要 npm install，没有任何第三方包。

停止服务：在运行窗口按 `Ctrl + C`。

```
┌───────────────────┬──────────────────────────────────────────────┐
│ 校园通 CampusQA   │  校园事务问答                                 │
│                   │  回答只来自校内资料，每条结论都带出处          │
│ ● 离线抽取模式     │ ┌──────────────────────────────────────────┐ │
│                   │ │ 我：宿舍水管漏水了怎么办                   │ │
│ 筛选知识库条目…    │ └──────────────────────────────────────────┘ │
│ ▸ 新生报到与入学材料│ ┌──────────────────────────────────────────┐ │
│ ▸ 宿舍分配与电费   │ │ 答：按《后勤服务指南》第 4 节的说明，       │ │
│ ▸ 宿舍设施报修流程 │ │ 「宿舍设施报修流程」主要是这几步：         │ │
│ ▸ 校园卡办理挂失   │ │  · 校园卡 App → 生活服务 → 在线报修 [1]   │ │
│ …（共 18 条）      │ │  · 涉及水电安全的紧急故障…30 分钟内到场 [1]│ │
│                   │ │  [依据充分] [资料抽取·离线] [1ms]          │ │
│                   │ │  ┌[1] 后勤保障处·维修中心 ─────────────┐  │ │
│                   │ │  └ 点击展开原文 ──────────────────────┘  │ │
│ 运营看板 / 新对话  │ │  有用 · 没用                              │ │
└───────────────────┴──────────────────────────────────────────────┘
```

界面要点：

- **左侧知识库导航**：18 条制度可以直接浏览、搜索、点开看原文
- **答案角标**：`[1]` 可点击，直接跳到对应资料原文抽屉
- **置信度标签**：以「依据充分 / 依据一般 / 依据较弱」呈现，而不是伪装成概率数字
- **生成模式标签**：明确告诉用户当前答案是「大模型生成」还是「资料抽取（离线）」
- **反馈按钮**：没用的问题会进入 `unanswered.jsonl`，成为补资料的依据
- **运营看板**：提问量、有效反馈率、低置信度占比、未答问题 Top、知识库校验结果

## 四、两种运行模式

### 4.1 离线抽取模式（默认）

不配置任何密钥即可运行。系统从检索到的原文中抽取最相关的句子组织成回答，**不存在编造数字的可能**，因为每个字都来自资料原文。

适合：演示、答辩、断网环境、对事实准确性要求最高的场景。

### 4.2 大模型模式

编辑 `app/config.json`：

```json
{
  "llm": {
    "enabled": true,
    "baseUrl": "https://api.deepseek.com/v1",
    "apiKey": "sk-你的密钥",
    "model": "deepseek-chat"
  }
}
```

或者用环境变量（优先级更高，密钥不落盘）：

```powershell
$env:QA_LLM_ENABLED="true"
$env:QA_LLM_API_KEY="sk-..."
node app/server.mjs
```

任何 **OpenAI 兼容接口** 都可以接：DeepSeek、通义千问、智谱 GLM、Kimi、本地 vLLM / Ollama 等，只要改 `baseUrl` 和 `model`。

大模型模式下，回答由模型组织语言，但事实仍来自注入的资料片段，并强制要求带 `[编号]` 引用。模型调用失败会自动降级到离线抽取，用户不会看到报错。

### 4.3 部署到线上（可选）

项目自带 `Dockerfile`、`render.yaml` 和 `.dockerignore`，可部署到 Zeabur / Render / Fly.io 等任意支持 Docker 的平台。

```powershell
git init && git add . && git commit -m "feat: campus-qa"
git remote add origin https://github.com/你的用户名/campus-qa.git
git push -u origin main
```

平台连上仓库后会自动识别 Dockerfile 构建。运行时只需在平台面板填环境变量：

| 变量 | 示例 |
| --- | --- |
| `QA_LLM_ENABLED` | `true` |
| `QA_LLM_BASE_URL` | `https://open.bigmodel.cn/api/paas/v4` |
| `QA_LLM_MODEL` | `glm-4-flash` |
| `QA_LLM_API_KEY` | 你的密钥（**只填平台面板，不要写进代码**） |

**云端自动启用的访问保护**（本地演示时用不到）：

| 保护 | 默认值 | 超限行为 |
| --- | --- | --- |
| 每分钟每 IP | 10 次 | HTTP 429，提示 N 秒后重试 |
| 每日每 IP | 30 次 | 降级到离线抽取，服务不中断 |
| 每日全局 | 600 次 | 降级到离线抽取，API 成本归零 |

大模型调用失败（401/超时）时**自动退还额度**，用户不会为服务端问题买单。

完整部署步骤、环境变量表、自检清单与常见问题见 **`docs/07_线上部署.md`**。

## 五、知识库怎么换成自己学校的
当前 `app/data/kb/` 下 18 条内容为**课程演示用示例数据**，金额、时间、电话均为虚构，不代表任何真实学校规定。界面顶部有常驻提示。

替换步骤：

1. 把本校的学生手册、迎新通知、后勤指南整理为 Markdown
2. 每条制度存成一个 `xxx.md`，头部写 front-matter：

```markdown
---
id: dorm-repair
title: 宿舍设施报修流程
tags: 报修, 维修, 水电, 漏水, 门锁
aliases: 宿舍东西坏了我该找谁, 水管漏水怎么办, 报修要多久
dept: 后勤保障处 · 维修中心
updated: 2025-08-22
source: 《后勤服务指南》第 4 节
---

## 报修渠道（三选一）
...
```

3. 保存后访问 `/admin` 点「重新加载知识库」，或重启服务

`tags` 和 `aliases` 是检索质量的关键：**aliases 要写学生真实会说的口语**（"宿舍东西坏了我该找谁"），而不是书面标题。

文档 `docs/02_AI工具链说明.md` 里给了用大模型把学校通知改写成结构化条目的提示词。

## 六、评测与调试

```powershell
# 端到端接口自测（需服务已启动）
node tools/smoke.mjs

# 主测试集评测（50 条）
node tools/eval.mjs

# 消融对比：关闭意图小节先验 + 证据特征
$env:QA_NO_SECTION_HINT="1"; $env:QA_NO_EVIDENCE="1"
node tools/eval.mjs --tag baseline

# 盲测集
node tools/eval.mjs --set tools/testset-blind.jsonl --tag blind

# 看某个问题为什么这样答
node tools/explain.mjs "图书馆开到几点"

# 命令行直接问一句
node tools/ask.mjs "宿舍报修找谁"

# 提示词三版对照实验（真实 API，需 Key）
$env:AB_API_KEY  = "sk-..."
$env:AB_BASE_URL = "https://open.bigmodel.cn/api/paas/v4"   # 智谱；DeepSeek 用 https://api.deepseek.com/v1
$env:AB_MODEL    = "glm-4-flash"
node tools/prompt-ab.mjs
```

当前指标见 `docs/04_评测报告.md`。

## 七、已知局限（写在前面）

1. **拒答判定靠规则**。中文短问句里"语料外口语词"太多，纯字面覆盖率区分度有限。盲测中"校园卡能借给同学用吗"被误答为图书馆借阅规则。
2. **同义词靠人工维护**。别名表覆盖不到的问法会落进拒答。系统用 0.25 秒级召回解决不了语义相似，比如"退宿"与"退学"。
3. **不支持多轮指代消解**。追问时"那它呢"这类指代只能靠历史文本拼接，效果有限。
4. **知识库是示例数据**，上线前必须换成本校官方文件。
5. **无并发与鉴权**。当前是单机演示形态，`/admin` 未做访问控制。

第 1、3 条的改进方向写在评测报告的「后续工作」里。
